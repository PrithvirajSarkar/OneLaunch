# OneLaunch — Future Ideas

This document contains features that may be considered for future
versions of OneLaunch.

These features are **not part of the current v1.0 scope** and will
only be implemented if they provide meaningful value to the application.

---

## Planned Future Features

### 1. Edit Item Path

Allow users to change the path of an existing application, file,
or folder without removing and adding the item again.

**Example:**
If an application is moved to a different location, the user can
update its path directly through the Edit Item option.

---

### 2. Import / Export

Allow users to export their workspaces to a file and import them
on another installation of OneLaunch.

**Possible uses:**
- Transfer workspaces to another computer
- Share workspace configurations
- Keep a portable copy of workspace data

---

### 3. Keyboard Shortcuts

Allow users to launch frequently used workspaces or perform common
actions using keyboard shortcuts.

**Possible shortcuts:**
- Launch workspace
- Search workspaces
- Create workspace
- Open OneLaunch

---

### 4. System Tray

Allow OneLaunch to remain available in the Windows system tray
without keeping the main window open.

Users could access frequently used workspaces directly from the
system tray.

---

## Lower-Priority Ideas

These features may be considered later but are not currently
prioritized.

### 5. Recent Workspaces

Display workspaces that were launched recently so users can quickly
access them again.

---

### 6. Backup / Restore

Provide user-controlled backups and allow previous workspace data
to be restored when necessary.

---

### 7. Workspace Templates

Allow users to create reusable templates for commonly used
workspace configurations.

**Example:**

A "College Project" template could contain:
- VS Code
- Browser
- Terminal
- GitHub

---

### 8. Notifications

Provide optional desktop notifications for events such as successful
workspace launches or launch failures.

---

## Permanently Dropped Features

The following features are intentionally excluded from the OneLaunch
roadmap:

- Duplicate Workspace
- Reorder Items
- Launch Statistics
- Favorites

### Reasons

**Duplicate Workspace**  
Not considered necessary for the intended workflow.

**Reorder Items**  
Not important enough to justify additional UI and implementation
complexity for the current design.

**Launch Statistics**  
OneLaunch is focused on launching workspaces rather than tracking
usage analytics.

**Favorites**  
The existing Pin/Unpin functionality already provides a way for
users to mark important workspaces.

---

## Scope Policy

OneLaunch should remain focused on its primary purpose:

> Organize applications, files, folders, and websites into reusable
> workspaces and launch them together with one click.

New features should only be considered when they provide clear value
without unnecessarily increasing the complexity of the application.
